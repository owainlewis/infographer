How AI Agents Actually Work

The Agent Loop — that's all there is
01
It's Stateless

Every LLM call starts from zero. There's no persistent thread. The "conversation" is the full message history re-sent every single time.

Key insight No hidden state
02
Tool Calls

The LLM doesn't "run" anything. It outputs structured JSON — function name + arguments. Your code executes it and feeds the result back.

Core mechanic JSON in, result out
03
Context Window

Everything the model knows must fit here: system prompt + history + tools + response. Overflow it and it silently forgets the beginning.

The bottleneck 128K–1M tokens
04
System Prompt

The "personality" is just a string prepended to every call. Not magic — it's the first message in the array. Change it any time.

Just a string First message
05
Memory

Agents don't "remember." Memory is text saved to a file or database, then injected into the next prompt. Persistence with extra steps.

Not magic Read → inject
06
RAG

Search first, then answer. Embed docs as vectors, find relevant chunks, paste them into the prompt. The LLM reads your data — it doesn't know it.

Retrieval Search → paste
07
Planning

When an agent "thinks step by step" it's generating text it reads back on the next loop. Planning is the model talking to its future self.

Self-prompting Think → read
08
Multi-Agent

Not a new architecture. It's agents calling other agents — one loop spawning another with a different system prompt and tool set. Nested while loops.

Nested loops Same pattern
09
Tokens

LLMs don't see words — they see chunks of ~4 characters. "unhappiness" is 3 tokens. You pay per token in, per token out. This is why context matters.

The unit ~4 chars each
!
Guardrails are your code's job, not the model's

The agent will happily delete your database if you give it a tool that can. Never trust the LLM to self-limit. Constraints live in the code that executes the tool calls.
