Load Balancer Algorithms

01 · Static
Round Robin

The default you'll inherit. NGINX ships with it. Requests go A, B, C, repeat. Deals cards evenly, but if one request downloads a file while another returns JSON, "even" still overloads one server.

Smells wrong when one server is hot but traffic looks "fair."

NGINX default Stateless
02 · Static
Weighted RR

What you switch to when servers aren't identical. Big instance next to a small one? Set weights. Canary deploy? 90% stable, 10% new build. Same cycle, some servers just show up more often.

Smells wrong when you scale but forget to update the weights.

Canary deploys Mixed hardware
03 · Dynamic
Least Connections

First dynamic algorithm most developers reach for. Watches who's still busy instead of counting dealt cards. A server stuck on a slow query stops getting new work. Handles WebSockets and streaming well.

Smells wrong when "5 conn" is fine on one host but killing another.

HAProxy Adaptive
04 · Dynamic
Least Response Time

When latency is the metric that matters. Measures actual response times and sends traffic to whoever answers fastest. Can oscillate: everyone floods the fast host, it slows, traffic shifts, repeat.

Smells wrong when latency spikes come in waves.

Latency-aware AWS ALB
05 · Distributed
P2C

Quietly routing your K8s traffic right now. Pick two random servers, send to the less busy one. Nearly as good as checking all of them, zero coordination. No herd stampede.

Default in Envoy, Istio, most service meshes.

Envoy / Istio Near-optimal
06 · Affinity
Consistent Hashing

Not about spreading load. About remembering where things go. User 42 always hits Server B. Add a server and only its neighbors' keys move.

Smells wrong when a hot key pins load to one server.
