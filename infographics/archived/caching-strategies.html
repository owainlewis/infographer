Caching Strategies

Read Patterns
01
Cache-Aside

The one you'll use 90% of the time. App checks cache first. Miss? Query the DB, then store the result. Your code controls everything.

Redis Most common
02
Read-Through

Cache-aside, but the cache loads itself. On a miss, the cache fetches from the DB automatically. Your app never touches the database for reads.

NCache Transparent
03
Refresh-Ahead

Refresh before anyone notices it's stale. When a key nears expiry, the cache proactively reloads from DB in the background. Users never see a miss.

Zero downtime Hot keys
Write Patterns
04
Write-Through

Cache and DB always in sync. Every write hits cache then DB. No ACK until both succeed. Zero stale reads, but every write pays double latency.

Consistency DynamoDB DAX
05
Write-Behind

Write-through's fast sibling. Write to cache, ACK instantly. Cache flushes to DB async. Massive throughput, but if cache dies before flush, data is gone.

High throughput Eventual
06
Write-Around

Skip the cache on writes entirely. Data goes straight to DB. Cache only fills when someone reads it. Keeps your cache clean of unread data.

Write-heavy Log data
