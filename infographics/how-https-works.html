How HTTPS Works

The TLS handshake explained — from client hello to encrypted data transfer.

B
Browser
S
Server
1

Client Hello

Browser sends supported TLS versions, cipher suites, and a random number to the server.

TLS 1.3 · ECDHE · AES-256-GCM

▼
2

Server Hello + Certificate

Server responds with chosen cipher suite, its own random number, and the SSL/TLS certificate containing the public key.

X.509 certificate · CA-signed · RSA/ECDSA

▼
3

Certificate Verification

Browser validates the certificate against trusted CAs, checks expiry, and verifies the domain matches.

Chain of trust · OCSP check · Certificate Transparency

▼
4

Key Exchange

Both sides perform Diffie-Hellman key exchange to derive a shared secret — without ever transmitting it over the wire.

ECDHE · Perfect Forward Secrecy

▼
5

Secure Connection Established

Both sides derive session keys from the shared secret. All subsequent data is encrypted with symmetric AES encryption.

AES-256-GCM · Session keys · ~50ms total
