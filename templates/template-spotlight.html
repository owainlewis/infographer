Database Scaling

The Core Problem
Vertical vs Horizontal

Every scaling decision starts here. Vertical scaling adds resources to one machine. Horizontal scaling adds more machines. Vertical is simpler but has a ceiling. Horizontal is harder but has no limit.

Start vertical Go horizontal when you hit the ceiling
Strategy 01
Read Replicas

Most apps are read-heavy. Route reads to replicas, writes to the primary. Replication lag is the tradeoff you accept.

80/20 rule PostgreSQL
Strategy 02
Sharding

Split data across databases by a key. User ID, region, tenant. Each shard handles a subset. Cross-shard queries become your new problem.

Vitess Citus
Strategy 03
Caching Layer

Don't hit the database if you don't have to. Cache hot reads in Redis or Memcached. Invalidation is the hard part.

Redis Cache-aside
