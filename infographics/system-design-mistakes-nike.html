10 System Design Mistakes

Common pitfalls senior engineers still make — and how to avoid them.

01

Premature optimization before measuring

Adding caching, sharding, or async processing before you have traffic data. Profile first, optimize second.

02

Choosing microservices on day one

Starting with 15 services and a message bus when a monolith would ship in a week. Complexity is not a feature.

03

Ignoring data consistency requirements

Using eventual consistency everywhere because it sounds modern. Some data needs strong guarantees — know which.

04

No defined failure modes

Every external dependency will fail. If you haven't designed the fallback, you've designed an outage.

05

Single database for everything

Postgres is great, but it's not an ideal search engine, cache, message queue, and analytics store simultaneously.

06

Synchronous calls in critical paths

Chaining five synchronous API calls means your p99 latency is the sum of all five. Use async where order doesn't matter.

07

Skipping capacity planning

Not doing back-of-envelope math on storage, throughput, and connections. A 10x growth shouldn't be a surprise.

08

No observability from the start

You can't debug what you can't see. Structured logging, metrics, and tracing should be in the first commit.

09

Designing for the wrong scale

Building for 10M users when you have 100. Or building for 100 when you know you'll have 10M in six months.

10

Not separating reads from writes

Read-heavy workloads need different patterns than write-heavy ones. CQRS isn't always overkill.
