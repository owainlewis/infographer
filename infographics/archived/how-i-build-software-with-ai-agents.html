How I Build Software
with AI Agents

01
Design

Write the spec before you write a single line of code. Start with a PRD. Define what you're building and why. Then write a technical spec covering architecture, data models, and constraints. A good spec means the agent gets it right first pass.

PRD Technical spec Architecture
02
Plan

Break the spec into small, well-defined tickets. Each ticket has clear inputs, outputs, and acceptance criteria. One task should take an agent minutes, not hours. Write them like you would for a junior engineer — specific file paths, expected behavior, edge cases.

Linear Task breakdown Acceptance criteria
03
Build

One agent per ticket. Isolated context. No bleed. Each agent picks up a single ticket and sees only what it needs: the spec, the relevant files, the acceptance criteria. A focused agent with 3 files of context outperforms a bloated agent with 50.

Claude Code Isolated context Sub-agents
04
Review

Separate agents review the code. Agents checking agents. Never let the same agent that wrote the code review it. Use dedicated review agents that check for quality, simplification, and consistency with the spec. Ask "can this be simpler?"

Simplification Quality Security
05
Ship

CI/CD runs. Tests pass. Human approves the final output. The human reviews the final diff, not every intermediate step. Your job shifts from writing code to reviewing architecture. You approve the what and the why. Agents handle the how.
