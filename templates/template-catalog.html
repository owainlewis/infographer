API Architectural Styles

01
RESTful

Uses standard HTTP methods. Statelessness, cacheability, and a uniform interface are key constraints. The most widely adopted style for web APIs.

Best for — Public APIs, CRUD apps, mobile backends, any service needing broad client compatibility.

HTTP verbs Stateless Cacheable Resource-based
02
GraphQL

Clients request only the data they need, offering flexible and efficient retrieval. Eliminates over-fetching and under-fetching problems with a typed schema.

Best for — Complex frontends, mobile apps with bandwidth constraints, aggregating multiple data sources.

Query language Single endpoint Typed schema
03
gRPC

High-performance RPC framework from Google using Protocol Buffers for efficient binary serialization. Ideal for low-latency service-to-service communication.

Best for — Microservice communication, streaming data, polyglot systems needing code generation.

Protobuf HTTP/2 Bi-directional Code-gen
04
WebSockets

Real-time, full-duplex communication over a single persistent connection. Perfect for chat, live feeds, and collaborative applications.

Best for — Chat apps, live dashboards, multiplayer games, collaborative editors like Figma.

Full-duplex Persistent Real-time Event-driven
05
SOAP

A protocol-based standard using XML, with built-in security, transactions, and ACID compliance. Common in enterprise and financial systems.

Best for — Banking, payment processing, enterprise integrations requiring strict contracts.

XML-based WS-Security WSDL contract
06
MQTT

A lightweight messaging protocol ideal for low-bandwidth networks, popular in IoT scenarios. Uses a publish-subscribe pattern for efficient delivery.

Best for — IoT devices, sensor networks, smart home systems, any constrained environment.

Pub/Sub Lightweight IoT-first QoS levels
