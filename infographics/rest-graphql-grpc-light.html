REST vs GraphQL vs gRPC

Three ways to build APIs — and when to use each one.

The Standard
REST
What It Is

Resource-based API style using standard HTTP methods. Each resource has a URL. Stateless, cacheable, universally understood.

Strengths
  • Universal — every language has an HTTP client
  • Cacheable — built-in HTTP caching
  • Simple — easy to learn and debug
  • Mature tooling — Swagger, Postman, curl
  • Browser-native — works without SDKs
JSON HTTP/1.1 OpenAPI Stateless
The Query Language
GraphQL
What It Is

A typed query language where clients request exactly the data they need from a single endpoint. Built by Facebook, open-sourced 2015.

Strengths
  • No over-fetching — get only what you ask for
  • Single endpoint — one URL for everything
  • Typed schema — self-documenting API
  • Real-time — subscriptions built in
  • Aggregation — combine multiple sources
Schema Resolvers Apollo Relay
The Performance Pick
gRPC
What It Is

High-performance RPC framework using Protocol Buffers for binary serialization over HTTP/2. Built by Google. Code-gen across 11+ languages.

Strengths
  • 10x faster than JSON serialization
  • Bi-directional streaming over HTTP/2
  • Code generation — typed clients for free
  • Strict contracts — .proto enforcement
  • Multiplexing — many calls, one connection
Protobuf HTTP/2 Streaming Code-gen
Weaknesses
  • Over-fetching and under-fetching
  • Multiple round trips for related data
  • No built-in schema or types
  • Versioning gets messy at scale
