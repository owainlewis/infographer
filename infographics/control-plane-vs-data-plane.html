Control Plane vs Data Plane

The Manager
Control Plane

Decides how work gets done. Rules, routing, config, and health.

The Worker
Data Plane

Where the actual work happens. Moves and processes data in real time.

Kubernetes
Low Volume

The API server, scheduler, and controller manager orchestrating the entire cluster state

Service Mesh
Config Push

Istiod pushing routing rules, mTLS certs, and retry policies to every sidecar proxy

AWS
Management

IAM, CloudFormation, and the console — defining who can access what and how it's provisioned

Kubernetes
High Volume

The kubelet and kube-proxy on each node, pulling images, running containers, and routing packets

Service Mesh
Hot Path

Envoy sidecars intercepting every request, applying retries, circuit breaking, and load balancing

AWS
Execution

EC2 instances running code, S3 serving files, RDS processing millions of queries per second

Why Separate Them

Update rules without touching live traffic. Scale each plane independently. Audit and secure them differently. Failures stay isolated.

What Most People Miss

The control plane is a single point of failure — design it for high availability. Security boundaries should always follow the plane split.
