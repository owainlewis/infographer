How to Test AI Applications

01 Trace
Trace First

Capture every request, response, and intermediate step. You cannot test what you cannot see. Find the most common queries and where things break.

Catches: regressions, latency spikes, error patterns.

"You find out from a customer that pricing answers have been wrong for 2 weeks."

Langfuse Nearly free
02 Dataset
Golden Dataset

Curate from real traces, not imagination. 10-20 examples per category. This defines what good looks like before you tune anything.

Catches: requirement gaps, edge cases.

"You're tuning prompts against vibes."

Requirements A weekend
03 Unit Test
Deterministic Tests

Cheap, fast, run on every PR. Mock the LLM, test your logic. Assert valid categories, check types, verify response schemas match.

Catches: schema violations, type errors, logic bugs.

"A schema change breaks downstream parsing and you find out in production."

pytest Cheap to run
04 Human Eval
Human Review

The step everyone skips. Have domain experts rate real outputs on defined criteria. Start binary: good or bad. Everything else calibrates against human judgement.

Catches: tone issues, hallucinations, quality drift.

"Your LLM judge gives high scores to hallucinated answers because they're fluent."

Gold standard Expensive & slow
05 LLM Judge
LLM-as-Judge

Use a strong model to grade outputs at scale, but only after human eval. Run model and human scores on the same 100 pairs. Meta-prompt to optimize the judge. Repeat until >90% aligned.

Catches: the same things as human eval, at scale.

"You're manually reviewing 500 outputs a week."

Braintrust Tokens, not hours
