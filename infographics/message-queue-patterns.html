Message Queue Patterns

01

Point-to-Point

One message, one consumer. The queue guarantees each message is processed exactly once. If the consumer dies, messages wait. The simplest reliable pattern.

Use when every job must happen exactly once. Order processing, email sending, payment handling.
Exactly-once SQS RabbitMQ
02

Pub/Sub

One message, many consumers. Publisher doesn't know who's listening. Each subscriber gets its own copy. Add new consumers without changing the publisher.

Use when multiple services need the same event. User signup triggers email, analytics, and provisioning.
Broadcast Kafka SNS
03

Competing Consumers

Scale horizontally by adding consumers. Multiple workers pull from the same queue. Each message goes to exactly one worker. More traffic? Add more consumers.

Use when throughput matters more than ordering. Image processing, report generation, batch jobs.
Horizontal scale Worker pools Backpressure
04

Dead Letter Queue

Where failed messages go to be investigated, not lost. After N retries, poison messages move to the DLQ instead of blocking the queue. Alert on DLQ depth.

Use when you need to handle failures gracefully. Every production queue should have one.
Fault tolerance Retry + inspect Safety net
