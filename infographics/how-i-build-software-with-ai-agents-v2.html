Agentic Engineering Workflow

01 Design
Write the Spec First

Start with a PRD. Define what you're building and why. Then a technical spec: architecture, data models, and constraints. A good spec means the agent gets it right first pass.

Tip: I spend more time on specs now than I ever spent on code.

PRD Technical spec
02 Plan
Break into Tickets

Small, well-defined tasks. Clear inputs, outputs, and acceptance criteria. Write them like you would for a junior engineer — specific file paths, expected behavior, edge cases.

Tip: If a ticket needs a paragraph to explain, it's too big.

Linear Acceptance criteria
03 Build
One Agent per Ticket

Isolated context. No bleed. Each agent sees only the spec, the relevant files, and the acceptance criteria. No shared state between agents.

Tip: A focused agent with 3 files outperforms a bloated agent with 50.

Claude Code Sub-agents
04 Review
Agents Checking Agents

Never self-review. Dedicated review agents check for quality, simplification, and consistency with the spec. This is the self-improving loop.

Tip: "Can this be simpler?" catches over-engineering humans miss.

Simplification Quality
05 Ship
Human Reviews Architecture

CI/CD runs. Tests pass. The human reviews the final diff, not every intermediate step. You approve the what and the why. Agents handle the how.

Tip: Your job shifts from writing code to reviewing architecture.
