9 Resilience Patterns

1
Circuit Breaker

Stops cascading failures by wrapping calls in a monitor that trips open after repeated errors, then slowly recovers.

Remote calls — APIs, databases, any external dependency that can hang or fail under load.

2
Retry with Backoff

Automatically retries failed operations with increasing delays to avoid overwhelming the target service.

Transient failures — network blips, rate limits, temporary unavailability, queue contention.

3
Bulkhead

Isolates components into independent pools so one failure doesn't sink the entire system. Like watertight compartments.

Shared resources — thread pools, connection pools, multi-tenant systems, critical path isolation.

4
CQRS

Separates read and write models so each can be optimized, scaled, and evolved independently.

High-read systems — dashboards, search, analytics where reads vastly outnumber writes.

5
Event Sourcing

Stores every state change as an immutable event. Replay the log to reconstruct any point in time.

Audit trails — finance, compliance, any domain where "why" matters as much as "what."

6
Saga Pattern

Manages distributed transactions as a chain of local transactions with compensating rollbacks on failure.

Microservices — order flows, payments, multi-service processes that need eventual consistency.

7
Sidecar

Attaches cross-cutting concerns (logging, auth, networking) as a separate process alongside your main service.

Service mesh — Envoy, Istio, any polyglot system needing uniform observability.

8
Strangler Fig

Gradually replaces a legacy system by routing traffic to new components one piece at a time. No big-bang cutover.

Migrations — monolith to microservices, platform rewrites, incremental modernization.

9
Rate Limiter

Controls throughput by capping requests per time window. Protects services from abuse, overload, and runaway clients.

Public APIs — auth endpoints, webhooks, any shared resource under unpredictable load.
