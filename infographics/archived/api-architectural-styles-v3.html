6 Patterns for API Design

01
REST

Uses standard HTTP methods with stateless, cacheable, resource-based design.

Best for — Public APIs, CRUD apps, mobile backends.

HTTP verbs Stateless Cacheable
02
GraphQL

Clients request exactly the data they need through a single endpoint. Typed schema prevents over-fetching.

Best for — Complex frontends, mobile apps, data aggregation.

Query language Single endpoint Typed schema
03
Webhooks

Reverse HTTP callbacks triggered by events. Your server registers a URL and gets notified automatically.

Best for — Payment notifications, CI/CD, third-party integrations.

Event-driven HTTP POST Async
04
gRPC

Google's high-performance RPC using Protocol Buffers and HTTP/2 with bidirectional streaming.

Best for — Microservices, real-time streaming, polyglot systems.

Protobuf HTTP/2 Streaming Code-gen
05
WebSockets

Full-duplex communication over a persistent TCP connection. Server pushes data instantly.

Best for — Chat, live dashboards, multiplayer games, editors.

Full-duplex Persistent Real-time Event-driven
06
SSE

Server-Sent Events over a single HTTP connection. How most LLM APIs stream tokens to the client.

Best for — AI streaming, live feeds, notifications, stock tickers.

One-way HTTP native Auto-reconnect AI streaming
