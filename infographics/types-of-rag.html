6 Practical Types Of RAG

01
Context Stuffing

Load the entire document into the prompt. No chunking, no embeddings, no infrastructure. Just read the file and send it.

Tip — With 200k+ context windows, this handles more than you think. Try it before building a pipeline.

Simplest No infra Long context
02
SQL RAG

Two flavors: text-to-SQL (LLM writes raw queries) or tool-use (agent calls functions that query the DB). No embeddings needed.

Tip — Criminally underrated. Tool-use is safer in production. Text-to-SQL is powerful but needs guardrails.

Structured Tool-use Text-to-SQL
03
Naive RAG

Chunk your docs, embed as vectors, embed the query, retrieve nearest neighbors by cosine similarity. The classic RAG pipeline.

Tip — The default when docs exceed context limits. Chunk size and overlap matter more than which embedding model you pick.

Semantic Cosine sim Embeddings
04
Keyword RAG

Full-text search with BM25. Tokenize, match terms, rank by relevance with document length normalization. No embeddings required.

Tip — Users search for error codes, product names, IDs. Vectors miss exact matches. Full-text nails them.

BM25 Exact match Proven
05
Hybrid RAG

Run semantic + keyword in parallel, then merge results with Reciprocal Rank Fusion. Better recall than either strategy alone.

Tip — The production sweet spot. Postgres can do pgvector + tsvector in one query. One database, both strategies.

Best recall RRF Production
06
Agentic RAG

The agent decides which retrieval strategy to use per query. Grep, read a file, vector search, SQL — it picks the right tool for the job.

Tip — Claude Code does this over codebases: grep, glob, read files. It's agentic RAG and it works extremely well.
