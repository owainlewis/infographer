Load Balancer Algorithms

01
Round Robin

Rotate through servers one by one. Each request goes to the next server in line. Works when all servers are identical and requests cost roughly the same.

Simple Homogeneous servers
02
Weighted Round Robin

Stronger servers get more traffic. Assign weights based on capacity. A server with weight 3 gets three requests for every one sent to a weight-1 server.

Weighted Mixed hardware
03
Least Connections

Send traffic to the server with the fewest active connections. Adapts in real time. Better than round robin when requests have variable processing times.

Adaptive Variable workloads
04
Least Response Time

Pick the server that responds fastest. Combines active connections with latency. Best when backend performance varies due to caching or data locality.

Latency-aware Health checks
05
IP Hash

Hash the client IP to always route to the same server. Sticky sessions without cookies. Breaks when clients share IPs or servers go down.

Sticky sessions Stateful apps
06
Consistent Hashing

Map servers to a ring. Adding or removing a node only moves nearby keys. Minimal redistribution during scaling. Powers every distributed cache and CDN.

Distributed Caches & CDNs
07
Random

Pick a server at random. No state, no coordination, no overhead. Statistically converges to even distribution at scale. Surprisingly effective for large pools.

Zero state Large pools
